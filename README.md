## 什么是 Vibe Coding

**Vibe Coding**（氛围编程）由前 OpenAI 联合创始人 Andrej Karpathy 提出，核心思想很简单：

```
以前写代码：  你想清楚怎么做 → 你一行行手写代码 → 你来回调试改 Bug
Vibe Coding：你说想要什么效果 → AI 写全部代码 → 你运行看看效果对不对
```

**一句话总结：你不再是写代码的人，而是用自然语言指挥 AI 写代码的人。**

### 你需要具备什么

| 需要 | 说明 |
|------|------|
| 🗣️ 能清楚描述你想要什么 | 比如"我想做一个能登录注册的任务管理网站" |
| 👀 能判断功能是否符合预期 | 跑起来点一点，看对不对——不需要看懂代码本身 |
| 🔄 愿意试错 | 效果不对就告诉 AI 哪里不对，让它改 |

### 你不需要具备什么

- ❌ 不需要背任何框架 API 或配置语法——AI 帮你查
- ❌ 不需要手写 SQL、CSS、XML——AI 帮你写
- ❌ 不需要提前画类图或 ER 图——AI 帮你设计
- ❌ 不需要会 Linux——全程在 Windows 上操作

## 第一步：搭建你的 AI 编程环境

> ⏱️ 首次约 30 分钟 | 只需做一次

### 1.1 三样东西

| 工具 | 是什么 | 怎么获取 |
|------|--------|---------|
| **Node.js ≥ 18** | Claude Code 的运行环境（类似 Java 需要 JRE） | [nodejs.org](https://nodejs.org) 下载安装，一路下一步 |
| **Claude Code** | AI 编程终端——你在这里和 AI 对话，AI 在这里读写你的文件 | 装好 Node.js 后，打开 PowerShell 输入安装命令 |
| **DeepSeek API Key** | 大模型服务——AI 的"大脑"，负责理解和生成代码 | [platform.deepseek.com](https://platform.deepseek.com) 注册获取 |

### 1.2 安装 Claude Code

打开 **PowerShell**（Win+R → 输入 `powershell` → 回车），依次输入：

```powershell
# 1. 确认 Node.js 装好了
node -v
# 应该显示 v18.x.x 或更高。如果没有，先去 https://nodejs.org 下载安装

# 2. 安装 Claude Code
npm install -g @anthropic-ai/claude-code

# 3. 验证安装成功
claude --version
# 显示版本号即成功
```

### 1.3 接入 DeepSeek（花费不到 5 元）

> 📖 参考官方指南：[DeepSeek 接入 Claude Code](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/claude_code)

**Step 1：注册并获取 Key**

1. 浏览器打开 [platform.deepseek.com](https://platform.deepseek.com)
2. 注册账号 → 左侧菜单「API Keys」→ 创建 Key → **复制并保存到记事本**
3. 顶部「充值」→ 充 10 元（够开发 3-5 个这种规模的项目）

**Step 2：配置 Claude Code**

打开 PowerShell，输入：

```powershell
# 创建配置目录和文件（如果还没有的话）
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.claude"
```

然后用记事本打开 `C:\Users\<你的用户名>\.claude\settings.json`，写入：

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "把这里换成你的DeepSeek API Key",
    "ANTHROPIC_MODEL": "deepseek-v4-pro",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "deepseek-v4-pro",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "deepseek-v4-pro",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "deepseek-v4-flash",
    "CLAUDE_CODE_SUBAGENT_MODEL": "deepseek-v4-pro",
    "API_TIMEOUT_MS": "600000",
    "CLAUDE_CODE_EFFORT_LEVEL": "max"
  }
}
```

> 💡 **为什么选 DeepSeek**：性价比极高。`deepseek-v4-pro` 负责复杂代码和深度推理；`deepseek-v4-flash` 负责快速问答和文件读取。相比 Claude 官方 API 节省 90%+。本项目全程 DeepSeek，总 API 花费不到 5 元。
>
> 💡 **超时设置**：`API_TIMEOUT_MS` 设 600000（10 分钟），因为复杂推理任务耗时较长，设短了会超时中断。
>
> ⚠️ **一个限制**：DeepSeek V4-Pro 是纯文本模型，不能识别图片。如果你上传截图或设计稿让它"照着做"，它会告诉你做不到。需要图片识别的话要切换回 Claude 原生模型。

**Step 3：验证配置**

```powershell
# 随便找个目录
mkdir ~/test-project
cd ~/test-project
claude
```

进入 Claude Code 后，输入：

```
/status
```

确认显示 `model: deepseek-v4-pro`。然后输入：

```
帮我创建一个 test.txt，内容是 Hello Vibe Coding
```

如果 AI 正确创建了文件——**环境就绪**。

### 1.4 给 AI 一份"员工手册"——CLAUDE.md

在项目根目录放一个 `CLAUDE.md` 文件，AI 每次打开项目都会先读它。**这决定了 AI 写出来的代码风格是不是你想要的。**

创建一个文本文件叫 `CLAUDE.md`，内容如下（可以直接抄）：

```markdown
# 开发规范（AI 必须遵守）

## 语言规则
1. 注释和文档用简体中文
2. 代码、变量名用英文

## 代码风格
- Java 类名用大驼峰：UserService
- 方法名用小驼峰：getUserById
- 缩进用 4 个空格，不要用 Tab
- 不要用 System.out 打印日志，用 SLF4J

## 项目结构
- 分层：Controller → Service → Mapper → Entity
- 不要凭空编造不存在的类或方法
```

> 📄 完整版参考本项目的 [CLAUDE.md](./CLAUDE.md)。
>
> 💡 **不用一次写全**。每次发现 AI 写出来的风格不对你胃口，加一条规则进去。迭代 3-5 轮后，AI 的代码就像你亲手写的一样。

## 第二步：怎么跟 AI 对话（核心方法论）

> ⏱️ 阅读 15 分钟 | **本文档最重要的章节**

### 2.1 核心原则：说需求，不说实现

这是 Vibe Coding 和"传统编程"最大的区别：

| ❌ 错误说法（指挥 AI 怎么做） | ✅ 正确说法（告诉 AI 要什么效果） | 为什么 |
|---------------------------|-------------------------------|--------|
| "用策略模式实现" | "支持多个模型，切换要方便，以后可能还会加新的" | AI 自己选了策略模式，可能比你选的更合适 |
| "建表，字段 id, content, role..." | "每条聊天消息要存下来，知道谁发的、发了什么、什么时候发的" | AI 设计的表结构不会漏字段，还会自动加索引 |
| "加个拦截器" | "没登录的人访问管理页面要提示登录" | AI 会选择最合适的实现方式 |

**记住一句话：你管"要什么"，AI 管"怎么做"。**

### 2.2 四类任务怎么跟 AI 说

#### 🆕 从零开始一个新项目

这是最重要的一种对话。第一次说清楚三件事就行：

```
帮我做一个 [什么类型的项目]
技术栈用 [后端框架 + 前端框架]
核心功能是：
  1. XXX
  2. XXX
  3. XXX

示例：
"帮我做一个任务管理网站，后端用 Spring Boot、前端用 Vue 3，
 核心功能是：新建任务、标记完成、按日期筛选和搜索。"
```

AI 会自动完成：创建项目结构 → 设计数据库 → 写接口 → 写前端页面 → 生成启动配置。

> 🔑 **不要一上来就描述几十个功能**。第一次说 3-5 个最核心的，跑通了再加。

#### ➕ 给已有项目加新功能

```
"给系统加一个 [功能名称]，要求 [1-2 个关键效果]"

示例：
"给任务管理加个分类标签功能，一个任务可以有多个标签，标签颜色可以自定义"
```

> 🔑 **一次只加一个功能，加完 commit，再加下一个。**一次让 AI 改太多容易出错。

#### 🔄 全局修改

```
"把系统所有的 [某个东西] 都改成 [新的样子]"

示例：
"把全站的按钮都改成圆角的"
"把所有的错误提示都改成中文"
```

> 🔑 **说清楚范围**："所有的"还是"只改 XX 页面"。

#### 🛠️ 让 AI 写工具脚本

```
"帮我写个脚本，自动 [做什么]，需要能 [交互方式]"

示例：
"帮我写个一键启动脚本，自动检测数据库有没有运行，没运行就启动它，
 然后问我要启动哪些服务，最后把访问地址打印出来"
```

> 🔑 **描述交互流程**——"先干嘛、再干嘛、最后干嘛"。技术细节 AI 自己搞定。

### 2.3 通用公式

```
[在哪] + [干什么] + [有什么限制] + [长什么样]

"在这个 Spring Boot 项目（在哪）
 加上 AI 对话功能（干什么）
 用流式输出，模型可以切换（限制）
 像 ChatGPT 那样打字机效果（长什么样）"
```

### 2.4 常见问题怎么处理

| 遇到什么 | 怎么办 |
|---------|--------|
| AI 改得太多结果半对半错 | 拆成 2-3 个小需求，分开问。每次 commit 后再问下一个 |
| AI 编造了不存在的类 | CLAUDE.md 加一句"禁止编造类，必须基于已有代码" |
| AI 理解错了 | 不要让它继续改，直接撤销（`git reset --hard`），换个说法重新说 |
| 代码跑不起来报错了 | 把报错信息直接复制粘贴给 AI："这个报错，帮我修复" |
| 代码风格不统一 | CLAUDE.md 里补充偏好规则，下一轮 AI 就会统一 |

### 2.5 推荐的开发节奏

```
第 1 次对话：跑通核心流程——能增删改查就行，丑一点没关系
第 2 次对话：加搜索、筛选、分页这些辅助功能
第 3 次对话：优化界面——Loading 动画、报错提示、空状态、手机上好不好看
第 4 次对话：工程收尾——.gitignore、启动脚本、文档
```

> 🎯 **每次对话不超过半小时，每次结束就 commit。** 这样出了问题随时可以回退。

## 实战案例：本项目完整开发过程

> 以下是本项目的真实 15 次对话记录。注意看我每次说了什么、没说哪些技术细节。

### 开发全景

```
项目：Ds-Ai 多模块 AI 聊天平台
周期：不到 2 天
对话：15 次，每次 20-40 分钟
花费：不到 5 元（DeepSeek API）
产出：后端 86 个类 + 前端 50+ 组件 + 30 张数据库表 + 4 份技术文档
```

### 每次对话用到了哪些参考文档

在每次对话中，我**只给 AI 自然语言需求 + 少量参考文档的关键片段**，没有给任何现成的代码或项目模板。AI 自己完成了全部架构设计。

| 对话主题 | 参考了什么（片段） | AI 据此做了什么 |
|---------|-----------------|---------------|
| 搭建 RBAC 权限系统 | 一份开源后台管理系统的功能列表描述 | 自己设计了 9 张表结构、JWT 认证流程、16 个接口 |
| 接入 AI 对话 | DeepSeek API 文档中的请求格式和响应示例（几行 JSON） | 自己写了 OkHttp 调用代码、SSE 流式解析、前端打字机效果 |
| 管理后台界面 | Element UI 官网组件列表和示例截图描述 | 自己拼出了完整的增删改查页面 |
| 代码风格约束 | 本项目的 CLAUDE.md | 全程遵守命名规范、分层架构、注释语言 |

> 🔑 **你不需要给 AI 完整文档，只需要给关键片段**。比如告诉 AI "API 返回格式是这样的：`{"choices":[{"delta":{"content":"你好"}}]}`"，它就能自己写出完整的流式解析逻辑。

### 15 次对话实录

| 次数 | 我说了什么 | AI 产出了什么 | 用时 |
|------|----------|-------------|------|
| 1 | "创建 Spring Boot + Vue 后台管理系统，要有用户、角色、菜单管理" | 项目骨架 + 9 张表 + JWT 认证 + 16 个接口 + Vue 后台页面 | 40min |
| 2 | "清理编译文件，配置 .gitignore" | .gitignore + 清理 Git 追踪 | 5min |
| 3-12 | "加 AI 对话——多模型、SSE 流式、会话管理、知识库、助手模板"（10 次迭代，每次加一个功能） | AiChatService + 5 个模型 Provider + 7 张 AI 表 + SSE 流式输出 + Chat 聊天组件 | 6h |
| 13 | "加 RAG 检索增强、中英文切换、对话收藏分享、后台管理 AI 配置" | rag/ 包（10 个文件）+ vue-i18n + 收藏/分享功能 + 模型管理后台 | 2h |
| 14 | "Vite 配置允许局域网访问" | 改 2 行配置文件 | 3min |
| 15 | "写一键启动脚本，自动检测 MySQL/Redis，支持公网穿透" | start-all.sh（240 行）+ stop-all.sh + Windows 批处理版 | 30min |

### AI 自己选了哪些技术方案

下面这些设计决策**我一句都没有指定**，全是 AI 在理解需求后自己选的：

| 需求 | AI 选了什么方案 | 为什么这样选 |
|------|-------------|-------------|
| 要支持 5 个不同 AI 厂商 | 策略模式 + 抽象工厂 | 加新厂商只需写 30 行代码 |
| RAG 向量存储要同时支持开发和生产 | 接口抽象 + 两个实现（内存版 / PostgreSQL 版） | 开发时零配置，上线一行切换 |
| AI 对话要实时打字效果 | SSE（Server-Sent Events） | 比 WebSocket 简单，够用 |
| 两个前端框架版本不同 | Vue 3 用 Pinia / Vue 2 用 Vuex | 根据版本自动匹配最佳方案 |

> 👆 **这就是"说需求不说实现"的威力——不需要懂策略模式和抽象工厂，AI 帮你选。**

## 轮到你了：开始自己的项目

看到这里，你已经知道了一个 Vibe Coding 项目的全貌。现在该你自己动手了。

### 第一次对话（选一个直接复制）

打开 PowerShell，进入你要放项目的目录，然后：

```powershell
mkdir my-project
cd my-project
claude
```

看到 Claude Code 的对话界面后，根据你的情况选一个：

**情况 A：我有明确想做的项目**
```
帮我创建一个 [项目类型]，技术栈用 Spring Boot + Vue 3。
核心功能：
  1. [功能 A]
  2. [功能 B]
  3. [功能 C]
数据库用 MySQL，缓存用 Redis。
```

**情况 B：我想练手但没具体想法**
```
帮我创建一个简单的任务管理 Web 应用。
功能：能添加任务、标记完成/未完成、按日期筛选、搜索任务标题。
后端用 Spring Boot，前端用 Vue 3，数据库用 MySQL。
```

**情况 C：我完全不知道做什么**
```
帮我创建一个个人博客系统。
功能：发布文章（标题+正文）、文章分类、标签、评论、后台管理。
前端用 Vue 3，后端用 Spring Boot，数据库用 MySQL。
```

### 后续迭代

第一次对话 AI 生成完代码后：

```bash
# 先保存当前成果
git init
git add -A
git commit -m "第一版：核心功能完成"

# 然后继续加功能，每次只加一个：
"帮我加个搜索功能"
"列表页加个分页，每页显示 10 条"
"登录页面太简陋了，优化一下，加个背景图和动画"
```

> 🎯 **每次对话只做一件事，做完就 commit。** 这是 Vibe Coding 最重要的纪律。

## 成果展示：这个项目能做什么

> 👇 这就是不到 2 天 Vibe Coding 的实际产出。

### 系统概览

| 模块 | 技术栈 | 端口 | 面向谁 |
|------|--------|------|--------|
| 后端 API | Spring Boot 2.7 + MyBatis + Redis + MySQL | `8090` | 为前端提供数据接口 |
| AI 用户端 | Vue 3.5 + Element Plus + Pinia + Vite | `5174` | 普通用户使用 |
| 管理后台 | Vue 2.7 + Element UI + Vuex + Vite | `5173` | 管理员使用 |

### 功能清单（共 30 项）

**系统管理**（8 项）：用户管理 · 角色管理 · 菜单管理 · 部门管理 · 岗位管理 · 字典管理 · 参数配置 · 通知公告

### 上线前 8 项检查

AI 写的代码能跑，但是能不能拿去给客户用、给用户用？逐项过一遍：

| # | 检查什么 | 怎么算通过 |
|---|---------|----------|
| 1 | 🔐 **登录保护** | 不登录直接访问页面，会被自动跳转到登录页 |
| 2 | 🔒 **密码安全** | 数据库里 `sys_user` 表的 `password` 字段是乱码（BCrypt 加密后的），不是明文 |
| 3 | 🚫 **防注入攻击** | 在输入框输入 `<script>alert(1)</script>`，提交后不会被浏览器执行 |
| 4 | ⏱️ **防暴力破解** | 同一个账号连续输错 5 次密码后，暂时无法继续尝试 |
| 5 | 📝 **操作可追溯** | 后台"操作日志"里能看到谁在什么时间做了什么操作 |
| 6 | 🖼️ **界面完整** | 每个页面都有 Loading 加载状态、错误提示语、无数据时的空状态提示 |
| 7 | 🌐 **跨域安全** | CORS 配置了具体的允许域名，而不是 `*`（允许所有人） |
| 8 | 📖 **接口文档保护** | 生产环境下，Swagger 页面不对外开放（或需要登录才能看） |

> 💡 以上 8 点，本项目在开发过程中已经逐项让 AI 实现了。你在让 AI 写代码时，可以把这 8 条直接作为需求告诉它。
